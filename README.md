# HER

영화 HER의 사만다처럼 먼저 말을 걸기도 하며 대화하는 AI 친구  
AI채팅 서비스는 이미 여럿 있지만 특정 세계관/컨셉에서 진행해나가는 서사중심인게 많고  
제대로 쓰려면 과금이 필요해서  
특정 설정이 아닌 평범한 현실에서, 낮은 비용으로, 친구와의 대화를 하는 컨셉으로 만듬.  

## 프로젝트 개요
  
영화 HER의 사만다 같은 '친구'와 대화하는 PC(Win)앱  
옛날 프로그램 중 '맥스와 대화하기' 같이 친구와 편하게 대화하는 AI채팅을 목표로 함  
부가적인 배경설정 같은것도 최소한으로 써서 가능한 저렴한 비용으로 사용할 수 있도록 하려 함  



## 개발 진행 방식

- 에이전틱 AI를 활용한 구현
  구현할 기능과 수정 방향을 제시하고, Codex가 저장소 구조 확인, 코드 작성, 테스트 및 오류 수정을 수행  
  생성된 결과는 동작을 확인하고 필요한 부분을 다시 수정  


## 주요 기능

- 친구 추가(이름, 특징이나 관계 등 설정)  
- 채팅으로 대화하며 친구가 선톡을 보낼 수 있음(설정에 따라), 실시간으로 계속 대화를 이어가는 '통화'모드 가능   
- 단톡도 가능하며 단톡에 참여할 친구를 선택하여 만들고, 친구들끼리 이야기를 하기도 함(설정에 따라)  
- SBV2 설치 시 답장을 음성으로 들을 수 있음(일음만 지원)

사용자는 텍스트로 대화하며 음성 입력은 내가 안쓸거라 추가하지 않음

## 현재 지원 범위

- Windows PC용 Electron 애플리케이션
- 여러 AI 친구와 각각의 1:1 대화방
- 기존 친구 2~6명을 선택해 만드는 단체 대화방
- 친구별 성격, 말투, 관계 상태, 선톡 및 음성 설정
- 읽음 표시, 답장 속도 반응, 메시지 검색과 기억 관리
- 설정에 따른 개인 선톡과 단톡 친구들의 자율 대화
- Style-Bert-VITS2를 이용한 로컬 음성 합성과 순차 재생
- 1:1 대화방의 통화형 연속 대화
- OpenAI 토큰 사용량과 지원 모델의 예상 비용 표시
- 트레이 상주, Windows 로그인 시 자동 시작, 백업과 복원

통화형 연속 대화는 현재 **사용자가 텍스트로 입력하고 AI가 음성으로 답하는 방식**입니다. 마이크 입력, 음성 인식(STT), 양방향 실시간 오디오 스트리밍은 아직 지원하지 않습니다.

## 실행

### 요구 사항

- Node.js 22.12 이상
- npm
- 실제 AI 응답을 사용할 경우 OpenAI API 키
- 로컬 음성을 사용할 경우 Style-Bert-VITS2 서버

의존성을 설치하고 개발용 앱을 실행합니다.

```powershell
npm.cmd install
npm.cmd start
```

OpenAI API 키가 없으면 앱은 데모 응답으로 동작합니다. 앱의 `앱·API 설정`에서 키를 저장하거나 환경 변수로 전달할 수 있습니다.

```powershell
$env:OPENAI_API_KEY="..."
npm.cmd start
```

앱에서 저장한 API 키는 Electron `safeStorage`를 통해 운영체제 계정에 묶인 형태로 보관하며, 상태 JSON이나 저장소 파일에 평문으로 기록하지 않습니다. `.env`와 로컬 상태·로그·음성 모델 데이터는 `.gitignore`에서 제외합니다.

## 테스트와 Windows 실행파일 빌드

## 대화 기능

AI 답장은 구조화된 형식으로 생성된 뒤 친구별 답장 속도 설정에 맞춰 전달됩니다. 사용자가 계속 타이핑하는 동안에는 잠시 기다렸다가 입력이 끝난 뒤 최근 메시지 묶음에 한 번에 답합니다.

친구는 설정에 따라 먼저 연락할 수 있습니다. 선톡은 최근 대화, 답하지 않은 메시지, 방해 금지 시간, 하루 자동 대화 토큰 한도와 친구의 선톡 빈도를 함께 고려합니다. 예정된 선톡을 끄면 남은 시간이 보존되며, 다시 켰을 때 이어서 예약됩니다.

단톡에서는 참여 친구 중 한 명이 문맥에 맞게 답하며, `친구들끼리 자율 대화`를 켜면 사용자가 말하지 않아도 친구들이 짧게 대화를 이어갑니다. 자율 대화는 단톡에서만 사용할 수 있습니다.

대화 기록 수정·삭제 기능은 기본적으로 꺼져 있습니다. `앱·API 설정`에서 허용하면 메시지를 수정하거나 삭제할 수 있으며, 이후 모델에 전달되는 대화 문맥에도 변경 내용이 반영됩니다. 사용자가 직접 밝힌 장기적으로 유용한 사실은 기억으로 저장할 수 있고, 기억 관리 화면에서 직접 추가·수정·고정·삭제할 수 있습니다.

## 통화형 연속 대화

1:1 대화방 상단의 `통화 시작` 버튼으로 시작합니다. 친구의 `답장 음성 생성`과 `새 음성 자동 재생`이 모두 켜져 있어야 합니다.

- AI 음성 재생이 끝난 뒤 잠시 침묵하면 같은 통화에서 이어 말하듯 다음 발화를 생성합니다.
- 사용자가 타이핑하거나 일반 답장이 생성 중이면 침묵 타이머를 미룹니다.
- 답장이 늦으면 같은 질문을 반복하거나 재촉하는 대신 하던 말을 보충하거나, 가볍게 혼잣말하거나, 화제를 자연스럽게 바꾸도록 지시합니다.
- 무응답이 반복되면 대기 간격을 늘리고 세 번째 무응답 전에 자동으로 통화를 종료합니다.
- 통화는 앱을 재시작하면 꺼진 상태로 시작하며 다른 대화방으로 이동하거나 대화를 초기화해도 종료됩니다.
- 기본값에서는 HER 창이 비활성화되거나 숨겨지면 통화를 종료합니다. `백그라운드에서도 소리 재생`을 켜면 백그라운드에서도 계속할 수 있습니다.
- 통화형 대화는 `자율·통화형 대화 모델`을 사용합니다. 기본 모델은 `gpt-5.6-luna`입니다.

통화형 대화의 토큰은 전체 및 월간 사용량에 포함되지만, 개인 선톡과 단톡 자율 대화에 사용하는 `하루 자동 대화 토큰 한도`에는 포함되지 않습니다.

## 로컬 음성 사용

채팅 화면과 기록은 한국어로 유지하고, 음성을 켠 친구의 새 답장에는 같은 의미와 말투의 일본어 낭독문을 함께 생성합니다. 음성 합성은 OpenAI 음성 API가 아니라 이 PC에서 실행 중인 Style-Bert-VITS2 서버가 담당하므로 별도의 음성 API 사용료는 없습니다. 일본어 낭독문 생성에 사용된 LLM 출력 토큰 비용은 발생할 수 있습니다.

### NVIDIA GPU Docker 실행 권장

직접 설치는 Python 및 PyTorch 패키지 버전 충돌이 발생하기 쉬우므로 Windows에서는 포함된 Docker 구성을 권장합니다. Docker Desktop의 WSL2 백엔드와 NVIDIA GPU를 사용하는 구성입니다.

1. Docker Desktop을 실행하고 Linux 컨테이너 모드인지 확인합니다.
2. 프로젝트 루트의 `start-sbv2-gpu.cmd`를 실행합니다.
3. 최초 실행은 CUDA 이미지, BERT 파일과 기본 음성 모델을 다운로드하므로 오래 걸릴 수 있습니다.
4. `logs-sbv2-gpu.cmd`에서 GPU와 API 서버 시작 메시지를 확인합니다.
5. HER의 `앱·API 설정`에서 서버 주소가 `http://127.0.0.1:5000`인지 확인합니다.
6. `친구 설정 → 로컬 음성`에서 `목소리 목록 불러오기`를 누른 뒤 목소리와 스타일을 선택합니다.

서버 종료는 `stop-sbv2-gpu.cmd`를 사용합니다. 내려받은 음성 모델은 `sbv2-data/model_assets`에, Hugging Face 캐시는 Docker 볼륨에 유지됩니다. 직접 받은 모델은 `sbv2-data/model_assets/모델이름/` 아래에 `config.json`, `*.safetensors`, `style_vectors.npy`를 함께 넣습니다.

직접 설치한 Style-Bert-VITS2를 사용할 수도 있습니다. 해당 설치의 API 서버를 실행한 뒤 HER의 서버 주소를 맞춰야 하지만, 패키지 구성과 실행 파일 위치는 Style-Bert-VITS2 버전에 따라 달라질 수 있습니다.

### 음성 생성과 실패 처리

`음성 준비 후 말풍선 표시`를 켜면 로컬 음성을 먼저 준비한 뒤 말풍선을 표시합니다. 원래 설정된 답장 지연 시간은 유지됩니다.

- 서버 연결 상태를 최대 3초 동안 먼저 확인합니다.
- 서버가 꺼졌거나 연결할 수 없으면 음성 대기를 해제하고 텍스트 말풍선을 표시합니다.
- 실패한 답장은 자동 재생 단계에서 같은 음성 합성을 다시 요청하지 않습니다.
- 말풍선이 여러 개여도 짧은 실패 상태를 공유해 서버를 반복 호출하지 않습니다.
- 서버를 다시 실행한 뒤 말풍선의 `▶` 버튼을 누르면 수동으로 다시 시도할 수 있습니다.
- 통화형 대화 중 서버 연결이 실패하면 생성된 텍스트는 표시하고 통화 모드만 종료합니다.

여러 말풍선의 음성은 앞 음성이 끝난 뒤 다음 음성을 재생하는 하나의 순차 대기열을 사용합니다. 각 WAV의 활성 음성 구간을 분석해 음량을 맞추고, 큰 피크를 억제하며 짧게 페이드인합니다. 긴 낭독문은 90자 이하로 분할 합성한 뒤 하나의 WAV로 결합하므로 SBV2의 100자 제한을 넘지 않습니다.

`ㅋㅋ`는 단독 `笑`, 메타 표기 `（笑）`, 그대로의 `ㅋㅋ`로 읽지 않도록 합성 직전에 발음 가능한 `ふふ`로 교정합니다. `笑う`, `笑顔`처럼 문장 의미에 필요한 일반 단어는 그대로 유지합니다.

기존 메시지에는 낭독문이 없을 수 있으므로 음성을 켠 뒤 새로 생성된 AI 메시지부터 재생할 수 있습니다. 합성된 WAV는 앱 데이터 폴더에 캐시됩니다.

## 자동 음성 말걸기와 백그라운드 동작

`자동 음성 말걸기`는 통화형 대화와 별개의 기능입니다. 사용자가 답하지 않아도 설정한 간격마다 친구가 짧게 말을 걸며, 필요하면 음성 내용을 채팅 기록에서 숨길 수 있습니다.

- 조용함: 8~15분
- 보통: 3~8분
- 수다스러움: 1분 30초~4분

설정한 연속 발화 횟수에 도달하면 15~30분 쉽니다. 이 기능에는 방해 금지 시간과 하루 자동 대화 토큰 한도가 적용됩니다.

기본값에서는 창이 활성 상태일 때만 새 음성을 자동 재생합니다. `백그라운드에서도 소리 재생`을 켜면 다른 작업 중이거나 창이 트레이에 숨겨진 상태에서도 재생합니다. 지나간 음성을 창을 열 때 한꺼번에 재생하지 않으며, 여러 친구의 음성도 서로 겹치지 않습니다. 트레이 메뉴의 `자동 음성 음소거`로 즉시 끌 수 있습니다.

창의 닫기 버튼은 기본적으로 앱을 종료하지 않고 시스템 트레이로 보냅니다. 완전히 종료하려면 알림 영역의 HER 아이콘을 우클릭해 `HER 종료`를 선택합니다. Windows 로그인 시 자동 시작을 켜면 `--hidden` 옵션으로 창 없이 실행되어 선톡과 알림을 처리합니다.

## 토큰과 예상 비용

OpenAI 응답의 실제 usage 값을 누적 입력·출력·캐시·요청 횟수로 나눠 기록합니다. 로컬 음성 합성에는 OpenAI 음성 API 비용이 없지만, 음성용 일본어 낭독문도 LLM 응답에 포함되므로 출력 토큰은 늘어날 수 있습니다.

예상 비용은 앱에 가격 정보가 등록된 GPT-5.6 Sol, Terra, Luna에 대해서만 계산합니다. 직접 입력한 다른 모델 ID도 요청에 사용할 수 있지만 가격을 알 수 없는 모델의 비용은 추정하지 않습니다.

GPT-5.6 요청에는 추론 강도 `none`, 낮은 출력 verbosity와 최대 30분의 명시적 프롬프트 캐시 설정을 사용합니다. 고정 지침과 친구별 설정을 캐시 가능한 앞부분에 두고 최근 대화와 현재 상황을 뒤에 배치합니다. GPT-5.6이 아닌 모델에는 이 전용 옵션을 자동으로 생략합니다.

## 데이터, 백업과 로그

친구 설정, 대화, 기억, 관계 상태와 사용량은 Electron `userData` 폴더에 저장됩니다. Windows 기본 위치는 `%APPDATA%\her-ai-friend`입니다.

- `state.json`: 친구, 대화방, 메시지, 기억, 설정과 사용량
- `voice-cache/`: 합성된 WAV 캐시
- `conversation-events.jsonl`: 생성 출처, 단계, 소요 시간, 토큰, 예약 및 전달 상태
- `voice-diagnostics.jsonl`: 화면용 한국어, 실제 낭독문, 모델·스타일, 분할 문장과 음성 성공·실패 상태

`앱·API 설정`에서 상태를 JSON 백업으로 내보내거나 복원할 수 있습니다. 진단 로그에는 문제 확인을 위해 일부 식별자와 음성 문장이 로컬에 저장될 수 있으므로 공유하기 전에 내용을 확인해야 합니다.

## 코드 구조

- `main.js`: Electron 생명주기, 트레이, 스케줄러와 IPC를 연결하는 조정 계층
- `preload.js`: 샌드박스 렌더러에 허용된 IPC 기능만 노출
- `src/main/state.js`: 저장 상태 생성, 정규화와 구버전 마이그레이션
- `src/main/usage.js`: 토큰·비용 집계와 사용 한도 판정
- `src/main/openai.js`: OpenAI 요청, 재시도, 응답과 usage 처리
- `src/main/scheduler.js`: 읽음·답장 속도, 선톡 간격, 방해 금지와 절전 복귀 규칙
- `src/main/message-history.js`: 메시지 수정·삭제와 연결된 기억 정합성 처리
- `src/app.js`: 채팅 화면 렌더링과 사용자 상호작용 조정
- `src/renderer/settings-data.js`: 친구 프리셋과 설정값 설명 데이터
- `src/renderer/settings-ui.js`: 친구·단톡 설정 폼의 UI 상태 제어
- `src/renderer/chat-view.js`: 말풍선과 대화방 목록의 안전한 HTML 생성
- `src/prompt.js`, `src/reply.js`: 프롬프트 생성과 모델 응답 검증
- `src/live-conversation.js`: 통화형 대화의 침묵 간격과 무응답 상태 규칙
- `src/rooms.js`, `src/memory.js`, `src/relationship.js`: 대화방·기억·관계 규칙
- `src/voice.js`, `src/voice-player.js`, `src/audio-queue.js`: 음성 요청, 음량 보정과 순차 재생
- `src/storage.js`, `src/cost.js`: 안전한 상태 저장과 예상 비용 계산
- `test/`: 도메인 단위 테스트, 저장 상태 마이그레이션과 UI 회귀 테스트

새 기능은 가능한 한 해당 도메인 모듈에 구현하고, `main.js`와 `src/app.js`에는 프로세스 간 연결과 화면 조정만 둡니다.

## 현재 제한사항

- Windows 중심으로 개발하고 있으며 다른 운영체제는 별도로 검증하지 않았습니다.
- 마이크 입력, STT와 실시간 양방향 음성 스트리밍은 지원하지 않습니다.
- 통화형 연속 대화는 1:1 대화방에서만 사용할 수 있습니다.
- 단톡 참여 인원은 AI 친구 최대 6명입니다.
- 로컬 음성은 별도로 실행한 Style-Bert-VITS2 서버가 필요합니다.
- 기본 음성 흐름은 한국어 화면 문장과 일본어 낭독문 조합입니다. 향후 한국어 음성 모델을 연결할 수 있도록 두 문장을 분리해 저장합니다.
